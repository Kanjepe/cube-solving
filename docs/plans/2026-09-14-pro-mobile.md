# Pro guides (2x2 Ortega + CLL, 3x3 CFOP, Pyraminx L4E/Oka) with the beginner mobile layout

Status: implemented 2026-09-16. The three standalone Pro blocks are generated by `_build/pro_blocks.py` from `_build/pro_cases.py` and `_build/pro_runtime.html`; `cube-solving.html` is rebuilt by `_build/assemble.py`. Deviations from the plan below: the runtime is a single template namespaced per guide (`.guide2pro`/`g2p-`, `.guide3pro`/`g3p-`, `.guidepypro`/`gpp-`) instead of three hand-maintained copies; the F2L picture renderer lives in the Pro runtime rather than in the shared renderers; the plan's per-file content and state tests were consolidated into `_build/test_pro_cases.py`, `_build/test_guidepro_content.py`, `_build/test_guidepro_state.cjs` and `_build/test_guidepro_browser.cjs`. Pre-change copies: `archive/2026-09-16-before-pro-*.html`; older archives (kids level, 2026-09-09/10 beginner snapshots, `_build/py-beginner.html`) were removed the same day and remain in git history.

Preview: the approved preview (`docs/plans/2026-09-14-pro-mobile-preview.html` and its generator sources) was removed on 2026-09-16 after implementation; it remains in git history before that date. Its generators became `_build/pro_cases.py` and `_build/pro_blocks.py`.

## Objective and scope

Move all three Pro sections to the page-by-page mobile format already used by the 2x2, 3x3 and Pyraminx beginner guides, and make them complete: every algorithm of each method is on the page itself, explained in the same plain language as the beginner guides. External links are additional reading at the end of each Pro block, never a substitute for content.

The reader model is: a complete beginner opens the site and the beginner level is enough on its own; someone who already solves with the beginner method switches to Pro and finds the same style of guidance with more cases.

Keep the standalone files authoritative and independently usable. Generate `cube-solving.html` through `_build/assemble.py`. Preserve every beginner block unchanged; the existing snapshot tests must keep passing without modification for beginner content.

## Findings from the current files

- The old Pro content is a long single page per puzzle: intro card, method sections, algorithm tables and a summary table. It has no per-page navigation, no saved progress and no move help. F2L had only three trigger moves, CLL had no algorithms at all.
- All algorithms in the current tables were replayed in `_build/verify_algs.py` (57 OLL, 21 PLL, 7 Ortega OLL, 5 PBL): each inverse leaves the first two layers (bottom corners for 2x2) intact and produces a genuine last-layer case. No correction is needed.
- The two missing lists were fetched and verified the same way: 42 CLL (speedcubedb, 40 cases in 7 orientation groups plus the two solved-orientation cases that equal the PBL T and Y perms) and the 41 F2L cases (speedsolving wiki; case 37 is the solved pair, so 40 algorithms). Every CLL inverse keeps the bottom layer; every F2L inverse keeps the cross and the other three slots and moves only the front-right pair. Whole-cube rotations inside these algorithms (`y`, `y'`, `d`) are handled by reading the picture in the learner's frame and relabeling colors so the front center is always green.
- The hand-authored Sune diagrams (3x3 OCLL and 2x2 OLL) match the simulator-derived stickers exactly, which confirms the diagram conventions: `data-c` reads the U face back row to front row, side strips follow the same axes, arrows use `[col,row]`.
- The Pyraminx L4E core reuses the three beginner step-3 algorithms verified in the Pyraminx phase, plus `R' L R L'`, `L R' L' R` and the two ELL U-perms, which are not yet covered by `_build/test_pyraminx_sim.py`.
- The 3x3 move help only explains R, L, U, D, F, B. Pro algorithms also use wide moves, slices and rotations; `verify_algs.Cube.MOVES` already models all of them.
- The unified shell requires `nav.steps.pro-nav` per puzzle. The beginner runtimes hide `nav.steps` when active rather than removing it; Pro will do the same.
- The 2x2 beginner block contains notes addressed to the author ("Tavs pazīstamais Sune", "Par Tavām divām citām sānu kombinācijām", "Par Tavu FINISH", "Tavs MIX"). They are out of scope for this plan but will read oddly to a public visitor; a separate decision is needed before deployment.

## Shared presentation contract

Reuse the beginner typography, 680px content width, spacing, card and callout styles, 46px buttons, collapsed panels, move-help dialog and fixed Previous / Steps / Next navigation. Namespace per file: `.guide2pro` / `g2p-*`, `.guide3pro` / `g3p-*`, `.guidepypro` / `gpp-*`. Storage keys `cube2-pro-v1`, `cube3-pro-v1`, `pyraminx-pro-v1`, each storing `{ page, done, learned, drill }`.

Pro accent: the existing `--cpro` purple for the eyebrow, primary buttons, focus rings, progress bar, group badges and source links. Move chips gain two colors: green for wide and slice moves, purple for whole-cube rotations. Beginner blue, green check and amber warning stay as they are.

Activity detection mirrors the beginner runtimes: in the unified page the block is active when `body[data-cube]` matches and `data-level="pro"`; standalone, when `body.pro` is set. The active class is per puzzle so three blocks in one document never clear each other's state. When active, hide `nav.steps`, `.panel-hero`, the shared `#uzbuve` / `#nota` sections, `footer` and `.mb-hint`, exactly as the beginner blocks do.

Language rules for Pro text: every term is explained in one sentence on first use in a "Vārdi, kas parādīsies tālāk" list on the intro page (slots, lukturi, 2-look, perm, sānu strīpas, OCLL, OLL/PBL, ELL, V forma, PK/PL/AM). Each solving page keeps the beginner order: goal, grip, what to inspect, cases, observable success criteria, recovery, done checkbox.

Shared components (each namespaced per file):

- **Case card**: one or two diagrams, case name, algorithm chips, one-line recognition hint, "Apgūts" checkbox. The same algorithm id may appear on several pages; the checkbox state is shared by id.
- **Group panel**: a `details` element titled by recognition shape with a `k / n` badge that turns green when complete.
- **Progress box**: "Apgūtie algoritmi: k no n" with a bar, computed from the cards in the block.
- **Drill page**: choose a set, get a setup sequence (the inverse of a case algorithm), recognise the case, reveal the answer, mark it learned. Unlearned cases first.
- **Reference page** ("Visi algoritmi"): every algorithm of the block in compact rows grouped as on the step pages, followed by the progress box and the source links with one-line descriptions.
- **F2L picture**: a new diagram kind showing the U face above the F face with the R face to the right; only the two pair pieces and the centers are colored, everything else grey. Added to the renderer in all three files and to `_build/shell-end.html`.

## Page specifications

### 3x3 CFOP (`guide3pro`), 4 numbered steps, 121 learnable algorithm ids

1. `intro` – what changes, the OLL-before-PLL warning, term list, new notation chips `r l u d f M S E x y z` with help, learning order, progress box.
2. `1` Cross – on the bottom, four edges found during inspection, eight-move target, checkpoint, recovery for swapped edges.
3. `2` F2L – pair idea; the four basic cases as cards; extraction moves; then all 40 cases in nine groups named by piece location (Pamata ievietošana 4, Malas pārvietošana 4, Mala jāpārvieto un stūris jāapgriež 6, Pāri atdala 4, Pāris savienots sānā 4, Īpašie 2, Stūris slotā 6, Mala slotā 6, Abi slotā 4), each group with a one-sentence description; look-ahead note.
4. `3` OLL – 2-look edges (3), 2-look corners (7 OCLL), all 57 in 14 shape groups.
5. `4` PLL – 2-look corners (T, Y) and edges (Ua, H), all 21 in five groups with side colors and arrows.
6. `drill` – sets: 2-look OLL edges, OCLL, 2-look PLL, PLL 21, OLL 57, F2L 40, all.
7. `algs` – reference page for all of the above.
8. `summary` – learning stages with typical times, progress box, sources.

### 2x2 Ortega + CLL (`guide2pro`), 4 numbered steps, 52 learnable algorithm ids

1. `intro` – three steps and twelve algorithms, CLL as the next level, term list, notation with `y`.
2. `1` One face – intuitive, checkpoint.
3. `2` OLL – seven cards with simulator-derived top views.
4. `3` PBL – "both solved" note plus five cards; each card has two pictures: the top layer and the bottom layer with the cube turned over keeping the same front.
5. `4` CLL – when to switch, grip, how to learn by group, all 42 cases in eight groups (Sune 6, Antisune 6, U 6, T 6, L 6, Pi 6, H 4, Augša jau dzeltena 2), method comparison table.
6. `drill` – sets: Ortega OLL 7, PBL 5, CLL 42, all.
7. `algs` – reference page with progress box and sources.

### Pyraminx L4E / Oka (`guidepypro`), 3 numbered steps, 7 learnable algorithm ids

1. `intro` – L4E and Oka, term list (V forma, ELL, PK/PL/AM), notation with tip moves.
2. `1` V shape.
3. `2` L4E – beginner top-view figure, intuitive route (cycles and flip), algorithmic core (Sledgehammer, Hedgeslammer).
4. `3` Oka – concept in four steps, five ELL cards, related methods.
5. `drill` – sets: L4E core, ELL, all.
6. `algs` – reference page with progress box and sources.

Pyraminx cards without a verified diagram (insertions, U-perms) stay text-only until the simulator gate below is passed; the full 35-case L4E list is a later phase once the Pyraminx picture convention for the upper edges is settled.

## Decisions taken in the preview

- Pro pages count only real method steps (4 for 3x3 and 2x2, 3 for Pyraminx); intro, drill, reference and summary are unnumbered.
- CLL is a full step page with all 42 algorithms, grouped by the Ortega OLL shape the reader already knows.
- F2L is complete (40 algorithms) but the page leads with the four basic cases and two extraction moves so a beginner can solve everything before learning the rest.
- PBL cards show both layers: top view and bottom view with the cube turned over keeping the same front.
- The old "Pro kopsavilkums" tables become a reference page per puzzle ("Visi algoritmi") plus a 3x3 summary page with learning stages; sources with one-line descriptions sit at the end of each block.
- Algorithm text is taken verbatim from the cited sources after simulator verification; parentheses are removed and `U2'` is written `U2`.
